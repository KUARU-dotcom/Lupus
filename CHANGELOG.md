# Changelog

## 0.6.0

Релиз V0.6: новая семантика логики и типов, консервативный GC, сеть,
асинхронность и публичный host-API для встраивания. Версия фиксирует итог
этапов A–F и release-гейты этапа G.

### Семантика

- `and`/`or` возвращают значение (семантика Scheme), действует единая политика
  типов builtins и проверки конкретных типов в конструкторах `defstruct`
  (ERRATA §13).

### GC

- Консервативный mark-and-sweep, разрыв циклов
  `env → container → closure` (GH-47), встроенная `(gc-collect)` и настраиваемый
  порог `LUPUS_GC_THRESHOLD` (ERRATA §14).

### Сеть

- Пакет `texas` по §3.3 спецификации и короткие алиасы; `lappland/malice` и
  `lappland/delay` с детерминированным сидом `LUPUS_MALICE_SEED` (ERRATA §15).

### Асинхронность

- Пакет `amiya` по §3.5, маршалинг через `SendValue` и snapshot-семантика
  `amiya/spawn` (ERRATA §16).

### Встраивание

- Публичный `lupus::kennel`: профили `pure`/`core`/`full`, host-нативы,
  fuel-лимит (GH-35, GH-36), `set-fuel!` и `lupus eval --import` (ERRATA §17).

### BREAKING

- `and`/`or` возвращают значение, а не только булево.
- `()` — литерал пустого списка, а не `none`.
- `head`/`tail`/`nth`/`empty?`/`contains?`/`length` на неверном типе дают
  `type-mismatch`, а не `none`.
- Конструкторы `defstruct` проверяют конкретные типы полей.

Семантика V0.6 подробно описана в [ERRATA §13](./docs/ERRATA.md) и
разделе «BREAKING CHANGES V0.6»; сценарии, для которых oracle v0.4.0 не
является эталоном, перечислены в `skip_reason` (`tests/oracle.rs`).

### Тесты

`cargo test` — 285 тестов в 22 сьютах, включая 3 LiF-гейта; clippy и fmt
проходят без предупреждений, fuzz-гейт — 10 000 программ без паник.

## 0.5.3

Патч-релиз по итогам фаззинга и ревью NikoGPT: закрыта утечка памяти в кэше
модулей, встроенные функции стали значениями первого класса, runtime-ошибки
получили позицию в исходнике, добавлена фаззинг-инфраструктура.

### Исправления

- **#45 (утечка памяти, major):** разорван `Rc`-цикл
  `окружение → замыкание → окружение`, из-за которого каждое определение
  с `lambda` в одном процессе теряло память. Замер на 20 000 прогонов одного
  и того же исходника в одном процессе: было **+21 МБ**, стало **+0.2 МБ**
  (уровень шума аллокатора). Внутреннее представление связей вынесено в
  `StoredValue`: замыкание, захватившее ровно своё окружение, хранится как
  `params + body + Weak<env>`; при чтении возвращается обычное
  `Value::Closure` с сильным окружением. Публичный API (`Closure`, `Value`,
  методы `Environment`) не менялся. Регрессия закреплена тестом
  `tests/memory.rs::module_function_does_not_leak_module_environment`, который
  краснеет без фикса.

### Новое

- **BUG-31 / BUG-42 (builtins как значения):** встроенные функции стали
  значениями первого класса — новый вариант `Value::Native` и таблица
  `builtins` вместо матча на ~300 строк. Работает передача встроенной функции
  как аргумента и присваивание имени:

  ```
  (list-map (list 1 -2) abs)                            ; → (1 2)
  (define f head) (f (list 1 2))                        ; → (some 1)
  (import senko) (define root senko/sqrt) (root 81.0)   ; → 9.0
  ```

  Добавлены функции высшего порядка `list-filter` и `list-fold`.
  Сообщения об арности теперь берут имя функции из таблицы.

- **Фаззинг-инфраструктура:** добавлен `cargo-fuzz` с двумя таргетами
  (`parse_eval` — лексер→парсер→интерпретатор, `lexer` — только лексер,
  с проверкой инвариантов позиций) и workflow `.github/workflows/fuzz.yml`:
  прогон по расписанию каждые 6 часов, затравка корпуса из `tests/golden` и
  `examples`, сохранение артефактов, автосоздание issue при находке.
  Таргет `parse_eval` пропускает входы с `exit`/`loop`/`while`/`for`, чтобы
  легитимные бесконечные программы не считались находками.

### Изменение поведения

- **BUG-36 (location в runtime-ошибках):** runtime/lint/type-ошибки, возникшие
  при вычислении узла AST, теперь содержат `location` с `line`, `col` и
  `span`. Раньше `location` был `null` для всех фаз, кроме `lex`/`parse`.
  `location = null` остаётся только для ошибок без привязки к исходнику:
  `io-error` до разбора, отказ spawn, `no-tests-found`. Для парсеров JSON это
  расширение схемы: поле появляется там, где раньше было `null`.

### Внутреннее

- **BUG-35 (типизированные ошибки):** удалён классификатор кодов по префиксу
  русского текста (`Error::new` / `infer_code`). Все места вызова переведены
  на явные хелперы (`Error::runtime`, `Error::arity`, `Error::type_mismatch`
  и т.п.). Устранена хрупкая зависимость от формулировок сообщений.
- **BUG-43 (семантика захвата в циклах):** поведение зафиксировано в
  спецификации (§1.3, дополнение рев. 1.1) и ERRATA §10. `while` даёт позднее
  связывание (как `while` в Python) — замыкания видят финальное значение;
  `for` создаёт свежее окружение на итерацию (как `let` в JS). Это намеренная
  семантика, не баг.

### Тесты

Новый `tests/memory.rs` (разрыв `Rc`-цикла), `tests/v06_builtins.rs`
(builtins как значения, арность из таблицы), расширены `tests/errors.rs`
(location в runtime) и `tests/integration.rs`. Итого **231 тест** (`cargo test`),
clippy без предупреждений, fmt чистый.

### Модули и импорт

- `(import senko)` — одноуровневый импорт с префиксом `senko/`; `(import (senko math))`
  сохранён для будущих мультимодульных пакетов (префикс — имя модуля).
- `:as` переопределяет префикс: `(import senko :as math)` → `math/`.
- `:all` вносит экспортируемые имена без префикса; конфликт — `import-collision`.
- Файловые модули ищутся в `stdlib/<имя>.lupus` и каталогах `LUPUS_PATH`,
  выполняются один раз (кэш по каноническому пути) и экспортируют только
  `define-public`. Цикл импортов — `import-cycle`.
- Нативные пакеты V0.5: `senko` (математика), `kaltsit` (файлы), `w` (тесты).

### Map и дженерик-структуры

- `Map` — упорядоченный по вставке список пар. Встроенные функции: `map`,
  `map-get`, `map-keys`, `map-values`, `map-has?`, `map-set`; ключ NaN запрещён.
- `(defstruct (Node a) (value a) (left (Option (Node a))))` — параметры-дженерики
  парсятся без HM-проверки. Конструктор `(Node ...)` и аксессоры
  `(Node-value n)` / `(node-value n)` работают без учёта регистра префикса.
- Паттерны структур и кортежей проваливают совпадение целиком, если не совпал
  хотя бы один подпаттерн.

### Ошибки и CLI

- `lupus ast` печатает детерминированный JSON AST (§7).
- `lupus eval "<выражение>"` вычисляет выражение и печатает значение.
- `lupus test` выдаёт JSONL (`test-start`, `test-pass`/`test-fail`, `test-summary`),

### Числа с плавающей точкой (Float)

Литералы `3.14`, `2.5e-3`, `0.5` (литералы `Number::Float`); арифметика
`int+int=int`, `float+float=float`, смешивание `int+float` — runtime-ошибка.
Деление: `int/0` — ошибка; `float/0.0 → inf`, `float/(- 0.0) → -inf` (IEEE, без
ошибки). `%` с float — ошибка. Конверсии `int->float`, `float->int` (усечение к
нулю), `str->float`, `float->str`. Равенство: `(= 1 1.0) → false`.
Унарный минус работает и для float: `(- x)` отрицает число с плавающей точкой,
`(- 0.0 x)` — разность двух float (в т.ч. получение `-0.0` через `(- 0.0)`).

### Кортежи (Tuple)

`(tuple 1 "a" true)` — арность 0+ любая. Доступ только через match-паттерн
`(tuple a b c)`; несовпадение арности — runtime-ошибка. Равенство поэлементное;
печать `(tuple 1 "a")`.

### Структуры (defstruct)

`(defstruct point (x int) (y int))` — аннотации типов парсятся, но не проверяются.
Автогенерация конструктора `(point 10 20)` и аксессоров `(point-x p)`. Аксессор на
чужую структуру — ошибка. Дубликат имени поля — ошибка `duplicate-struct-field`.
match-паттерн `((point x y) ...)` связывает поля позиционно.

### Цикл loop/exit

`(loop тело...)` — бесконечный цикл; `(exit n)` — немедленное завершение процесса
с кодом n.

### Тест-система LiF (выпускные ворота)

`tests/golden/` (точный stdout, exit 0), `tests/negative/` (подстрока ошибки,
exit ≠ 0) и `tests/coverage_map.toml` (карта покрытия: у каждого символа ≥1
positive и ≥1 negative). Харнес `tests/lif.rs` прогоняет всё при `cargo test` и
проваливает сборку при падении любого файла.

### Бенчмарк

См. раздел ниже: результат `validate_tasks.py`.

### Устойчивость лексера: комментарий с одиночной `;`

Одиночная `;` (не обязательно `;;`) теперь начинает комментарий до конца строки.
Раньше одинокий `;` вне строки не потреблялся лексером и приводил к зависанию
(бесконечный цикл токенизации). Символов с `;` в языке нет, поэтому семантика
валидных программ не изменилась. Добавлен регрессионный тест и guard-таймаут
5 секунд в харнесе LiF (никакой `.lupus` не может повесить `cargo test`).
