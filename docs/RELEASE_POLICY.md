# Политика релизов (Release Policy)

## Версионные теги

- Версионные теги — **только lowercase SemVer** вида `vX.Y.Z`
  (например `v0.3.1`), **аннотированные** (`git tag -a`).

## Оформление релиза

Релиз = **тег** + **GitHub Release**:

1. Аннотированный тег `vX.Y.Z` на коммите `main`.
2. Сборка бинарников **из тегового коммита** (Linux нативно, Windows — кросском
   через mingw).
3. GitHub Release с артефактами: `lupus-vX.Y.Z-linux-x86_64.tar.gz`,
   `lupus-vX.Y.Z-windows-x86_64.zip` + `SHA256SUMS`.

## Исторические теги-«папки»

Архивные срезы оформляются **каталогами** (например `docs/`, `legacy/`),
а не ветками и не версионными тегами.

Теги прошлого, не являющиеся версиями, объявлены **историческими артефактами**:

- `Prototype`
- `V0.1e`
- `V0.1R`
- `V0.2`
- `Documentation_and_Specification`

Они **НЕ удаляются и НЕ переименовываются** — сохраняются как есть, для истории.

## Дубль Prototype / V0.1e

Дубль тегов `Prototype` и `V0.1e`, указывающих на один и тот же коммит,
сохранён как есть (исторический артефакт), без исправления.
