# Release Notes — Lupus V0.5.3

Дата: 2026-10-28
Тег: v0.5.3
Коммит: см. тег `v0.5.3`

## Что нового

### Утечка памяти в кэше модулей закрыта (#45)

Определение функции через `lambda` в одном процессе теряло память: цепочка
`окружение → замыкание → окружение` образовывала `Rc`-цикл, который не
разбирался при выходе. На CLI это было не видно (процесс живёт один запуск),
но `Interpreter` — публичный API библиотеки, и хост, крутящий много коротких
скриптов в одном процессе, тёк на каждое определение.

Замер: 20 000 прогонов одного и того же исходника в одном процессе.

| Сценарий | До | После |
|---|---|---|
| `(+ 1 2)` (контроль) | +0.2 МБ | +0.2 МБ |
| `(import fnmod) (fnmod/inc 1)` | **+21 МБ** | **+0.2 МБ** |
| `(define f (lambda (x) (+ x 1))) (f 1)` | **+21 МБ** | **+0.2 МБ** |

Закреплено тестом `tests/memory.rs`, который проверяет именно разрыв цикла
через `Weak::upgrade()`, а не размер RSS — флака не будет.

### Встроенные функции стали значениями

Раньше `(list-map (list 1 -2) abs)` падало с «Переменная 'abs' не определена»:
встроенные функции не были значениями. Теперь они первоклассные:

```lisp
(list-map (list 1 -2) abs)                             ; → (1 2)
(define f head) (f (list 1 2))                         ; → (some 1)
(import senko) (define root senko/sqrt) (root 81.0)    ; → 9.0
```

Добавлены `list-filter` и `list-fold`. Внутри таблица `builtins` заменила
матч на ~300 строк.

### Runtime-ошибки теперь с позицией

Ошибки, возникшие при вычислении узла AST, больше не имеют `location = null`:

```json
{"phase":"runtime","code":"type-mismatch","message":"+ требует чисел",
 "location":{"file":"/tmp/loc.lupus","line":2,"col":1,
             "span":{"start":13,"end":22}}}
```

Это расширение схемы §6.1. `location = null` остаётся только там, где ошибка
не привязана к исходнику: `io-error` до разбора, отказ spawn,
`no-tests-found`.

### Фаззинг

В репозитории появилась фаззинг-инфраструктура: `cargo-fuzz` с таргетами
`parse_eval` и `lexer`, workflow по расписанию каждые 6 часов, затравка
корпуса из `tests/golden` и `examples`, сохранение артефактов, автосоздание
issue при находке. Первые прогоны: `lexer` — 2.4 млн исполнений на `cov: 747`,
`parse_eval` — 293 тыс. на `cov: 3649`, падений нет.

## Breaking changes от V0.5.2

- **`location` в runtime-ошибках.** Кто парсит JSON по схеме §6.1 и ожидает
  `location = null` для `runtime`, увидит объект. Изменение расширяющее, но
  поведение другое.
- **Ошибки без кода больше не классифицируются по тексту.** Удалён
  `Error::new` / `infer_code`; код ошибки теперь всегда задаётся явно. На
  пользователя не влияет, на сторонние `use lupus::error::Error` — влияет.

## Известные ограничения

- **#47:** фикс #45 закрывает циклы `окружение → замыкание → окружение`, но
  не циклы через контейнеры (`окружение → список → замыкание → окружение`).
  `(define-mutable l (list)) (set! l (append l (list (lambda () 1))))` течёт
  по-прежнему. Списки, накапливающие лямбды в глобальной переменной, —
  основной риск для встраивания (`kennel`, V0.6). Полное решение требует GC
  или обхода значения при `define`/`set!`.
- **#35 / #36:** в интерпретаторе нет лимита вычислительных шагов (fuel).
  Скрипт с бесконечным циклом подвешивает процесс — для встраивания в чужой
  хост это неприемлемо. Планируется `fuel-exhausted` в V0.6.
- HM-тайпчекер не реализован (V1.0). Аннотации типов проверяются
  синтаксически.
- Tensor (`exusiai`) отложен в V2.0.
- macOS-сборка не поставляется (нужен Apple SDK).

## Установка

```bash
wget https://github.com/KUARU-dotcom/Lupus/releases/download/v0.5.3/lupus-v0.5.3-linux-x86_64.tar.gz
tar xzf lupus-v0.5.3-linux-x86_64.tar.gz
./lupus --version
```

Из исходников:

```bash
git clone https://github.com/KUARU-dotcom/Lupus.git
cd Lupus && cargo build --release
./target/release/lupus --version
```
